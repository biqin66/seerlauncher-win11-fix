# 赛尔号启动器（SeerLauncher）"获取游戏"无反应 — 问题分析与修复存档

> 存档日期：2026-06-28
> 适用机器：Windows 11 Pro，Build 26200，仅 C 盘
> 启动器路径：`C:\Program Files (x86)\SeerLauncher`

---

## 一、问题现象

在启动器主界面点击 **"获取游戏"** 按钮，**没有任何反应**：不弹安装目录对话框、不开始下载、不报错。多次点击均无效。

---

## 二、排查过程

### 1. 日志线索

启动器日志 `%APPDATA%\SeerLauncher\log\log_20260628.txt` 末尾出现 4 条（对应点击 4 次）：

```
download-game 游戏目录:undefined
download-game 游戏目录:undefined
download-game 游戏目录:undefined
download-game 游戏目录:undefined
```

每次都打印"游戏目录:undefined"后便没有下文 —— 说明处理函数中途退出了。

日志中还反复出现：

```
获取硬盘空间失败:Error: Command failed: wmic logicaldisk where deviceid="D:" get size,freespace
'wmic' 不是内部或外部命令...
```

以及启动时：

```
游戏目录:undefined
游戏目录不存在
get regkey:GameDir result:null
```

### 2. 反编译主进程（app.asar）

主进程代码 `resources/app.asar` → `main.js` 经过字符串数组混淆，反混淆后定位到三段关键逻辑：

- `ipcMain.handle('download-game', ...)` —— "获取游戏"按钮的后端处理
- `initGameState()` —— 启动时初始化游戏安装目录
- `lib/FileUtil.js` 的 `getWindowsDiskSpace()` —— 查询磁盘剩余空间

---

## 三、根本原因（三个缺陷叠加）

### 缺陷 1：`wmic` 在 Windows 11 已被移除

`getWindowsDiskSpace()`（`lib/FileUtil.js`）通过命令行执行：

```js
exec(`wmic logicaldisk where deviceid="${driveLetter}:" get size,freespace`, ...)
```

但 **Windows 11（Build 26200）已删除 `wmic` 命令**（本机实测 `wmic` 不存在），该调用直接报错。

### 缺陷 2：仅有 C 盘时，初始化硬编码探测 D/E 盘

`initGameState()` 在启动器位于 C 盘时，会去探测 D、E 盘来决定默认安装目录：

```js
let drive = path.parse(getAppPath()).root.substring(0,1);   // = 'C'
let gameDir = CacheUtil.get(GAME_DIR);                        // 首次为 null
if (!gameDir) {
    try {
        if (drive == 'C') {
            let dSpace = await getWindowsDiskSpace('D');       // ← 这里抛异常
            gameDir = 'D:/';
            ...
        } else gameDir = getAppPath();
        CacheUtil.set(GAME_DIR, gameDir);                      // ← 异常时执行不到
    } catch (e) { /* 仅打印"获取硬盘空间失败" */ }
}
```

本机**只有 C 盘**，加上缺陷 1，`getWindowsDiskSpace('D')` 抛异常被 catch 吞掉，
导致 **游戏目录 `GAME_DIR` 永远没有被写入，保持 undefined**。

### 缺陷 3：`download-game` 对空目录无兜底，崩在 `path.parse(undefined)`

点击"获取游戏"时：

```js
let gameDir = CacheUtil.get(GAME_DIR);               // → undefined
LogUtil.log('download-game 游戏目录:' + gameDir);    // → "download-game 游戏目录:undefined"
let drive = path.parse(gameDir).root.substring(0,1); // ★ 这一行在 try 之外！
try {
    let disk = await getWindowsDiskSpace(drive);
    ... mainWindow.webContents.send('show-change-install-dialog', ...);  // 弹安装对话框
} catch (e) { ... }
```

`gameDir` 为 `undefined` 时，`path.parse(undefined)` 抛
`TypeError: The "path" argument must be of type string`，
**且这行在 try/catch 之外**，导致整个 async 处理函数 reject、中途崩溃，
后面的 `show-change-install-dialog`（弹出安装对话框）根本发不出去。

### 因果链小结

> Windows 11 删除 `wmic` → 启动器靠 `wmic` 探测磁盘来设默认游戏目录，失败且无兜底
> → 游戏目录为空 → "获取游戏"对空目录调用 `path.parse(undefined)` 抛异常（且未被 try 包住）
> → 处理函数崩溃，安装对话框发不出来 → 按钮"无反应"。

## 四、修复方案

### 目标效果（按用户需求：一切按启动器相对路径走）

- 游戏安装到：`C:\Program Files (x86)\SeerLauncher\Games\NewSeer\`
- 下载包临时位于：`C:\Program Files (x86)\SeerLauncher\Download\`

### 四处改动

| # | 文件 | 改动 | 作用 |
|---|------|------|------|
| ① | `lib/FileUtil.js` | `getWindowsDiskSpace` 弃用 `wmic`，改用 Node 原生 `FS.statfs`，并以 PowerShell `Get-CimInstance Win32_LogicalDisk` 兜底；盘符不存在时返回 0 而非抛异常 | 根治"无反应"，且初始化不再崩溃 |
| ② | `main.js` `initGameState` | 盘符判定 `_0x197652=='C'` → `=='Z'`，使 C 盘时也走 else 分支 `gameDir = getAppPath()` | 游戏目录默认取启动器目录，无需写注册表，且与运行身份无关 |
| ③ | `main.js`（安装定位 `gameDownloadCompleted`） | "C盘特判" `getAppPath().indexOf('C:')==0x0` → `==0x9`（恒假），关闭"重定向到 AppData" | 安装路径恒走 `GameDir` 相对逻辑 |
| ④ | `main.js`（修复重装找包逻辑） | 同上，第二处 `('C:')==0x0` → `==0x9` | 修复重装时也在启动器目录找下载包，保持一致 |

> 改动②③④均在混淆后的 `main.js` 上做最小化字符替换，并通过 `node --check` 语法校验；
> 重新打包时保留了 `app.asar.unpacked/plugins/pepflashplayer32_15_0_0_152.dll` 的 unpacked 状态。

### `getWindowsDiskSpace` 新实现（替换 `wmic`）

```js
function getWindowsDiskSpace(driveLetter) {
    return new Promise((resolve) => {
        var drivePath = driveLetter + ':\\';
        if (typeof FS.statfs === 'function') {
            FS.statfs(drivePath, (err, st) => {
                if (!err && st) {
                    var total = st.blocks * st.bsize;
                    var avail = st.bavail * st.bsize;
                    resolve({ total: total, free: avail, available: avail });
                } else { psDiskSpace(driveLetter, resolve); }
            });
        } else { psDiskSpace(driveLetter, resolve); }
    });
}
function psDiskSpace(driveLetter, resolve) {
    var cmd = 'powershell -NoProfile -Command "$d=Get-CimInstance Win32_LogicalDisk -Filter \\"DeviceID=\'' + driveLetter + ':\'\\"; if($d){[string]$d.FreeSpace+\' \'+[string]$d.Size}"';
    exec(cmd, (error, stdout) => {
        if (!error && stdout && stdout.trim()) {
            var p = stdout.trim().split(/\s+/);
            var free = parseInt(p[0]), total = parseInt(p[1]);
            if (!isNaN(free) && !isNaN(total)) { resolve({ total: total, free: free, available: free }); return; }
        }
        resolve({ total: 0, free: 0, available: 0 });
    });
}
```

### 关于"以管理员运行"

游戏与下载包都落在启动器目录（通常是 `C:\Program Files (x86)\SeerLauncher`）这个受保护位置，
普通权限写不进去（这也正是原版加"C盘特判、重定向到 AppData"的原因）。因此当安装目录在
`Program Files` 下时，补丁器会把启动器设为 **始终以管理员身份运行**
（`HKLM\...\AppCompatFlags\Layers` 写入 `~ RUNASADMIN`，对全机用户生效）。

> 若启动器装在可写目录（非系统盘 / 非 Program Files），则普通权限即可，补丁器不会设管理员运行。

## 五、补丁文件与使用方法

修复以 **「通用补丁器」** 形式交付：它修改**本机自己的 `app.asar`**（自动适配各版本、各安装位置），
而非分发一个固定的成品包。本目录文件清单：

| 文件 | 说明 |
|------|------|
| `通用补丁器\seer_patch.js` | 补丁器核心（纯 Node.js，无第三方依赖） |
| `通用补丁器\一键补丁.bat` | 一键运行（自动提权 + 定位 Node） |
| `通用补丁器\README.md` | 通用补丁器使用说明 |
| `修复说明.md` | 本文档 |

### 使用步骤

1. 安装 [Node.js](https://nodejs.org)。
2. 关闭启动器，把整个 **`通用补丁器`** 文件夹复制进 SeerLauncher 安装目录内
   （如 `C:\Program Files (x86)\SeerLauncher\通用补丁器\`）。
3. 进入该文件夹双击 **`一键补丁.bat`**，UAC 点"是"。脚本会自动：
   1. 由"自己所在文件夹的上一级"定位安装目录；
   2. 备份原 `app.asar` 为 `app.asar.bak`（仅首次，保留最初原版）；
   3. 解析本机 asar、修补 `FileUtil.js`（去 wmic）与 `main.js`（相对路径）、重打包写回；
   4. 安装目录在 `Program Files` 时，设启动器以管理员身份运行。
4. 双击启动器，点 **"获取游戏"**，安装对话框正常弹出，确认后即开始下载安装。

> 补丁器**幂等**：对已打补丁的 asar 再次运行会识别并跳过；版本不匹配会安全中止，不写出损坏文件。

### 还原方法

1. 把 `<安装目录>\resources\app.asar.bak` 改回 `app.asar`；
2. 若设过管理员运行，删除注册表 `HKLM\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers`
   下名为启动器 exe 路径的那个值。

## 六、注意事项

- **每次启动需点一次 UAC**：这是把游戏放进 `Program Files` 的代价。若不想每次提权，
  可改用"放开 `SeerLauncher` 文件夹写权限（icacls 授予 Users 修改权）"的方案，
  即可让启动器以普通权限运行并正常写入。
- **为什么远程 asar 版本（1.0.14）反而比本地（1.0.16）低**：这两个版本号来自不同位置 ——
  本地版本来自安装包自带的 `config\app.config`（`asar_version = 1.0.16`），远程版本来自服务器
  `config.json` 的 `asar.version`（`1.0.14`），二者由发行方各自独立维护、并未对齐。关键佐证是
  **同一份远程配置里 web 反而是超前的**（远程 web `1.0.27` > 本地 `1.0.26`，所以 web 会被更新），
  唯独 asar 落后 —— 这种"一个超前、一个落后"的不对称，说明你安装的 `SeerLauncher_setup.exe` 是在
  较新的时间点打包、里面塞的是当时最新的 asar（1.0.16），而服务器那份 OTA 配置的 asar 版本号还停在
  1.0.14（没跟着升、或被回滚过）。此外该远程配置疑似 **测试/预发布版本**（`app.hash` 为占位假值
  `"sdfsdfsda"`、游戏地址指向内网 IP `10.1.6.212`），其中的 `1.0.14` 多半只是个旧的/测试用的值，
  并非真实生产版本号。**这是发行方侧的版本不一致，与本机无关。**

- **未来更新可能覆盖补丁**：正因为 `远程(1.0.14) < 本地(1.0.16)`，启动器永远判定"asar 不需要更新"，
  不会下载覆盖 `resources\app.asar`，所以本补丁可持久保留。唯一风险窗口：若日后发行方把服务器上的
  asar 版本号升过 `1.0.16`（如 `1.0.17`），启动器就会下载官方 asar 覆盖掉补丁 —— 那时要么官方新版
  本身已修复此问题，要么重跑一次 `通用补丁器\一键补丁.bat` 重新打补丁即可（补丁器会自动适配新版本、
  并重新生成备份）。

## 七、技术备注（关键定位）

- 远程配置：`https://newseer.61.com/launcher/config.json`（启动时拉取，含 games / app / web / asar 版本信息）
- 当前默认游戏：`defaultGame = 3`（nick = `NewSeer`，启动程序 `Seer.exe`，安装包约 188 MB，解压后约 692 MB）
- 缓存存储：注册表 `HKCU\Software\Taomee\SeerLauncher\Cache`（REG_SZ），游戏目录键名 `GameDir`
- 安装路径推导：
  - 下载包：`<GameDir>\SeerLauncher\Download\`（当 `GameDir == 启动器目录` 时为 `<启动器目录>\Download\`）
  - 解压安装：`<GameDir>\SeerLauncher\Games\<nick>`（当 `GameDir == 启动器目录` 时为 `<启动器目录>\Games\<nick>`）
  - 原"C盘特判"会把解压目录强制改为 `<userData>\games\<nick>`（已在补丁③中关闭）
